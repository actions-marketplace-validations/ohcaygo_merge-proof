What the service provides

Merge Proof provides independent exact-state merge evidence for pull requests. It records what available evidence establishes about an observed head, base and applicable merge state. It is not an AI code reviewer and does not write or merge code for you. No AI model decides the verdict.

  • VERIFIED: available evidence satisfies the implemented checks for the stated scope and exact observed state.
  • NOT_PROVEN: the available evidence does not establish everything required. This does not mean bad, broken or unsafe code. Read the receipt’s gaps and limitations.
  • CURRENT / STALE: freshness is separate from the original verdict. CURRENT means refreshed evidence still matches the receipt; STALE means relevant evidence changed. Without a fresh observation, currentness can be unavailable. A receipt is not an ongoing guarantee.

You remain responsible for reviewing the evidence, choosing repository policies and deciding whether to merge. Availability, supported GitHub evidence and technical capacity limits apply.
